# Numa Architecture

Numa uses Feature-Sliced Design (FSD) within WXT's browser-extension structure. WXT runtime entrypoints are the App-level composition roots; there is no parallel `src/app` layer.

## Runtime boundaries

The current UI runtimes are the options page mounted by `src/entrypoints/options/main.tsx` and the popup mounted by `src/entrypoints/popup/main.tsx`. Entrypoints own application composition only. Product behavior, persistence, messaging, and provider integrations have not been implemented yet. The popup contains one action that opens the browser-managed options page.

## Current structure

```text
src/
├── entrypoints/
│   ├── options/
│   │   ├── main.tsx
│   │   └── router/ # Options-only router factory, file routes, and generated route tree
│   └── popup/
│       ├── api/    # Popup-specific browser API adapters
│       └── ui/     # Popup root component
├── pages/
│   ├── settings/         # Route-level shell with flat private UI, navigation model, and local lib
│   └── general-settings/ # General route content
└── shared/               # Independently reused styles, UI, and libraries
```

Only create an FSD layer, slice, or segment when it has a current responsibility. Widgets, Features, and Entities are absent until product behavior requires them.

## Dependency direction

Entrypoints may import their local runtime modules and focused public APIs from lower FSD layers. The options file routes compose the Settings and General settings Page public APIs. Page slices do not import one another; route files perform that composition.

Shared remains independent of Pages and entrypoints. Shared exposes focused module APIs such as `src/shared/ui/Button/index.ts` and `src/shared/lib/cn/index.ts`; it has no global layer barrel. Files within a slice use relative imports and do not import back through their own public API.

## Ownership

### Options entrypoint

- `src/entrypoints/options/main.tsx` mounts the router and loads global styles.
- `src/entrypoints/options/router/router.ts` creates the router with hash history for the browser and accepts injected history for tests.
- `src/entrypoints/options/router/routes` owns file-route composition only.
- `src/entrypoints/options/router/routeTree.gen.ts` is generated by the TanStack Router Vite plugin and committed as generated source.

### Pages

- `src/pages/settings` owns the route-level shell, compact header, settings navigation metadata, responsive Sidebar implementation, and page-local media-query hook. Private Sidebar support files are flat within its `ui` segment.
- `src/pages/general-settings` owns the initial General route presentation.
- Each Page exposes a focused root `index.ts`. Private UI support stays inside its owning slice.

### Popup entrypoint

- `src/entrypoints/popup/main.tsx` mounts the popup and loads global styles.
- `src/entrypoints/popup/ui/App.tsx` renders the popup root with one settings button.
- `src/entrypoints/popup/api/openOptionsPage.ts` adapts `browser.runtime.openOptionsPage()` for the UI.

### Shared

Shared contains only modules with current independent consumers. Global semantic styles/tokens, `cn`, and `Button` are shared today. Single-owner support code starts with its owning Page, Feature, or entrypoint and moves to Shared only after an unrelated reuse case exists.

## Architecture enforcement

Run `pnpm lint:arch` for FSD structure and public-API checks with Steiger. ESLint enforces import boundaries, browser-global restrictions, cycles, React, accessibility, and TypeScript quality. `pnpm check` runs formatting, ESLint, Steiger, TypeScript, and tests.
